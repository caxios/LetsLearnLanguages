# 💰 수익화 아키텍처 설계

## 현재 비용 구조 분석

이 앱은 **AI API 호출 비용이 유저 수에 비례**하는 구조입니다:

| 기능 | API | 비용 발생 시점 |
|------|-----|---------------|
| 오늘의 문장 생성 | Gemini | 매일 3문장 생성 시 |
| 주제별 연습 생성 | Gemini | 유저가 주제 선택할 때마다 5문장 |
| 번역 평가 | Gemini | 유저가 번역 제출할 때마다 |
| 복습 채점 | Gemini | 복습 카드 제출할 때마다 |
| 음성 인식 (비활성) | OpenAI Whisper | 녹음 제출할 때마다 |

> **중요**: 무료 유저가 무제한으로 쓰면 API 비용이 수익을 초과할 수 있습니다.
> **사용량 제한(일일 쿼터)** 이 수익화의 핵심입니다.

## 티어 설계안

### 🆓 무료 (Free)

| 항목 | 제한 |
|------|------|
| 오늘의 문장 | 매일 3문장 (현재와 동일) |
| 주제별 연습 | 하루 **1회** (5문장) |
| 번역 평가 | 하루 **5회** |
| 복습 | 하루 **3회** |
| 새 문장 받기 (리프레시) | ❌ 불가 |
| 음성 입력 (Whisper) | ❌ 불가 |
| 광고 | ✅ 배너 + 인터스티셜 |
| 리워드 광고 | ✅ 시청 시 평가 2회 추가 |

### ⭐ 프리미엄 (Premium, 구독)

| 항목 | 제한 |
|------|------|
| 오늘의 문장 | 매일 3문장 + 새 문장 받기 무제한 |
| 주제별 연습 | **무제한** |
| 번역 평가 | **무제한** |
| 복습 | **무제한** |
| 음성 입력 (Whisper) | ✅ 활성화 |
| 광고 | ❌ 없음 |

### 💎 가격 (안)

| 플랜 | 가격 | 비고 |
|------|------|------|
| 월간 구독 | ₩4,900 / 월 | 부담 없는 진입 |
| 연간 구독 | ₩39,000 / 년 (₩3,250/월) | ~34% 할인, 장기 유지 유도 |

## 광고 전략 (Google AdMob)

### 광고 유형별 배치

#### 1. 배너 광고 (Banner)
- 위치: 오늘의 문장 탭 하단
- 크기: Adaptive Banner
- 노출: 무료 유저만, 항상 표시

#### 2. 인터스티셜 광고 (Interstitial)
- 시점: 번역 평가 결과를 본 후, 결과 화면에서 뒤로 나갈 때
- 빈도: 매 2~3회 평가마다 1번
- 대상: 무료 유저만

#### 3. 리워드 광고 (Rewarded)
- 시점: 일일 평가 횟수를 다 쓴 후 "광고 보고 2회 추가" 버튼
- 보상: 평가 2회 추가
- 대상: 무료 유저만
- 하루 최대: 3번 (= 최대 6회 추가)

### 유저 경험 원칙
- 광고가 **학습 도중**에 끼어들면 안 됨 (번역 작성 중, 피드백 읽는 중에는 절대 X)
- 인터스티셜은 **결과 화면을 떠나는 전환 시점**에만 표시
- 리워드 광고는 **유저가 자발적으로 선택**할 때만 재생

## 기술 스택

### 광고: `react-native-google-mobile-ads`

```
npm install react-native-google-mobile-ads
```

- Google 공식 React Native AdMob 라이브러리
- Expo Config Plugin 지원 → `app.json`에 설정만 추가하면 됨
- 배너, 인터스티셜, 리워드 광고 모두 지원
- **Expo Go에서는 작동 안 함** → EAS Build (Development Build) 필요

### 인앱 결제: `react-native-purchases` (RevenueCat)

```
npm install react-native-purchases
```

- RevenueCat이 서버 사이드 영수증 검증, 구독 상태 관리, 갱신/취소 처리를 전부 해줌
- 직접 서버 만들 필요 없음
- Expo Config Plugin 지원
- Google Play + App Store 동시 지원
- 무료 플랜: 월 수익 $2,500까지 무료 (초기에 충분)
- 대안인 `react-native-iap`는 영수증 검증 서버를 직접 만들어야 해서 1인 개발에 부담됨

> **팁**: RevenueCat은 "구독 상태"를 클라우드에서 관리하기 때문에, 유저가 앱을 삭제하고 다시 깔아도 구독이 유지됩니다. `react-native-iap`로 직접 구현하면 이런 것도 전부 직접 만들어야 합니다.

## 구현 아키텍처

### 새로 추가할 파일들

```
src/
├── constants/
│   ├── features.ts          # Feature flags (VOICE, ADS, IAP 등)
│   └── monetization.ts      # 티어별 쿼터 상수, 가격 ID, AdMob unit ID
├── stores/
│   └── useMonetizationStore.ts  # 구독 상태, 일일 사용량 추적
├── hooks/
│   ├── useQuota.ts           # 남은 평가/연습 횟수 조회
│   └── useSubscription.ts    # RevenueCat 구독 상태 훅
├── components/
│   ├── ads/
│   │   ├── BannerAd.tsx      # 배너 광고 컴포넌트
│   │   ├── InterstitialAd.tsx # 인터스티셜 관리
│   │   └── RewardedAd.tsx    # 리워드 광고 + 보상 처리
│   └── paywall/
│       └── Paywall.tsx       # 프리미엄 구독 유도 모달
├── services/
│   └── revenue.ts            # RevenueCat 초기화 및 구매 처리
```

### 핵심 데이터 흐름

```
유저가 평가 요청
  → 프리미엄인가?
    → Yes → 바로 평가 실행
    → No  → 일일 쿼터 남았는가?
              → Yes → 평가 실행 → 쿼터 -1
              → No  → 쿼터 초과 모달
                        → 리워드 광고 보기 → 광고 시청 → 쿼터 +2 → 평가 실행
                        → 프리미엄 구독 → Paywall 표시 → 구독 완료 → 바로 평가 실행
```

### `useMonetizationStore.ts` 핵심 구조

```typescript
interface MonetizationState {
  // 구독 상태 (RevenueCat에서 동기화)
  isPremium: boolean;
  subscriptionPlan: 'monthly' | 'yearly' | null;
  expiresAt: string | null;

  // 일일 사용량 추적 (로컬, 매일 자정에 리셋)
  dailyUsage: {
    date: string;            // 'yyyy-MM-dd'
    evaluationCount: number; // 오늘 평가한 횟수
    topicPracticeCount: number; // 오늘 주제별 연습 횟수
    reviewCount: number;     // 오늘 복습 횟수
    rewardedAdsWatched: number; // 오늘 리워드 광고 시청 횟수
  };
}
```

## 개발 순서 제안

```
Phase 1: EAS Build 세팅 + Development Build 생성
         → Expo Go를 벗어나 네이티브 모듈 사용 가능한 환경 만들기
         → 안드로이드 폰에 설치하여 테스트

Phase 2: 사용량 제한 시스템 (쿼터)
         → useMonetizationStore, useQuota 훅
         → 쿼터 초과 모달 UI
         → 광고/결제 없이도 Free 티어 제한 먼저 구현

Phase 3: Google AdMob 연동
         → 배너, 인터스티셜, 리워드 광고 구현
         → AdMob 콘솔에서 앱 등록 + 광고 단위 생성

Phase 4: RevenueCat 인앱 결제
         → RevenueCat 대시보드 설정
         → Google Play Console에서 구독 상품 등록
         → Paywall UI + 구독 상태 연동

Phase 5: Google Play 스토어 출시
         → 스토어 등록정보 작성
         → 프로덕션 빌드 (.aab) 생성 및 업로드
         → 심사 제출
```

## 결정이 필요한 사항

1. **티어 구분**: 위의 Free/Premium 구분과 쿼터 숫자가 괜찮은지?
2. **가격**: ₩4,900/월, ₩39,000/년이 적절한지?
3. **리워드 광고 보상**: 광고 1회 시청 = 평가 2회 추가가 적절한지?
4. **인터스티셜 빈도**: 매 2~3회 평가마다 1번이 너무 잦거나 드문지?
5. **Google Play 개발자 계정**: 이미 있는지? (등록비 $25 일회성)
6. **RevenueCat 계정**: 만들 의향이 있는지, 아니면 `react-native-iap`로 직접 할지?
